# 旅游规划（Travel Planner）

为用户的旅行提供"未来近一周"的完整情报与路线规划。

## 铁律：先问城市

**在拿到用户明确说出的目的地城市之前，禁止开始任何查询与规划。**
用户没说城市名时，必须停下来，向用户询问以下信息（城市为必问项，其余可选，但一次问清，不要连环追问）：

1. **目的地城市**（必问）
2. 出发城市 / 出发地（用于计算大交通）
3. 计划出行日期与天数（默认"未来近一周"）
4. 偏好（交通方式、预算、同行人如老人小孩）

示例提问："你想去哪个城市旅游？大概哪天出发、玩几天？从哪出发？"

## 执行流程

拿到城市名后，按以下顺序执行：

### 第 1 步：解析城市

- 有 `AMAP_KEY` 时：运行 `scripts/amap_api.py geocode "<城市名>"` 获取 adcode 与经纬度。
- 无 key 时：用 `general_search` 确认城市所在省份、城市 adcode（用于后续搜索口径），不要编造。

### 第 2 步：自然因素（未来近一周）

目标：未来 7 天逐日的天气、气温、降水概率、风力、空气质量、日出日落，以及穿衣/防晒/雨具建议。

1. 有 `AMAP_KEY` 时：运行 `scripts/amap_api.py weather <adcode>`（高德预报覆盖今日 + 未来 4 天）。
2. 用 `general_search` 补全 7 天预报与空气质量（关键词示例："<城市> 一周天气预报"、"<城市> 空气质量"、"<城市> 日出日落时间"），必要时 `web_fetch` 精读天气网站页面。
3. 信息冲突时以官方气象源（中央气象台、当地气象局）为准，标注来源与日期。

### 第 3 步：人文因素（未来近一周）

目标：本周该城市可参与的活动、展览、演出、节日节庆、热门景点开放状态、特色美食。

- 用 `general_search` 并行检索（一次最多 3 个关键词）：
  - "<城市> 本周活动 展览 演出"
  - "<城市> 最近 节庆 节日"
  - "<城市> 热门景点 开放时间"
- 对关键活动用 `web_fetch` 精读官方/权威页面（文旅局、景区官网、票务平台）核实时间、地点、是否需要预约。
- 标注"已核实"（来源页）与"一方称"（自媒体）的区别。

### 第 4 步：路线规划与耗时

1. 根据人文/自然信息挑选 3~5 个核心景点，安排每日行程（按地理位置就近分组，避免来回折返）。
2. 有 `AMAP_KEY` 时：对同一天相邻景点调用 `scripts/amap_api.py route "<起点经纬度>" "<终点经纬度>" <walking|driving|transit>`，获得距离与耗时；把各段耗时累加，给出每日路线总耗时。
3. 无 key 时：用 `general_search` 查"<景点A> 到 <景点B> 怎么走 多久"，或直接请用户提供高德 API Key（见下）；搜索结果要标注来源与估算属性。
4. 输出每日行程时给出：景点顺序、交通方式、单段耗时、当日总移动耗时、建议出发时间。

### 第 5 步：输出结构化报告

按以下结构交付（可用 Markdown 表格，关系复杂时配可视化）：

1. **目的地**：城市、省份、最佳出行窗口
2. **未来 7 天逐日情报表**：日期 | 天气 | 气温 | 降水/风力 | 空气质量 | 日出日落 | 穿衣/雨具建议
3. **本周人文清单**：活动/展览/演出/节庆 | 时间 | 地点 | 预约要求 | 来源
4. **推荐行程（按天）**：每天 | 景点顺序 | 交通方式 | 单段耗时 | 当日总耗时 | 备注
5. **注意事项**：天气风险（暴雨/高温）、景区限流预约、证件、费用估算
6. **数据来源与口径**：列出每个结论的来源，估算项明确标"估算"

## 高德地图（AMAP）使用规范

- 高德负责：地理编码、天气（4 天）、路径规划（距离/耗时）。这是"必要时刻"的首选数据源。
- API Key 从环境变量 `AMAP_KEY` 读取，或运行脚本时用 `--key` 传入；**绝不在报告、日志或对话中回显完整 Key**。
- 没有 Key 时：先尝试请用户提供（说明用途与获取方式：高德开放平台 console.amap.com 免费申请），用户不愿提供则用搜索降级，并在报告中注明"路线耗时为估算，未使用高德实时数据"。
- 脚本返回 JSON，解析失败时检查网络与参数，不要臆造结果。

## 事实纪律

- 每个数字与结论必须来自脚本真实返回、搜索真实结果或用户输入；查不到就写"未获取到"，不编造。
- 未来天气属于预报，报告要注明"预报仅供参考"。
- 涉及景区开放、预约、票价等易变信息，提示用户出行前再次核实。
